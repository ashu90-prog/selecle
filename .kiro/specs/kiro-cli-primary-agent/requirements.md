# Requirements: Kiro CLI as the primary agent

## Introduction

selecle runs AI agents in two roles: **spirits** (short headless runs that edit files on a git
branch) and **the Crypt** (the common agent that reads the shared context and answers with a JSON
plan). Until now three agent CLIs were offered side by side, with Claude Code as the default.
This feature makes **Kiro CLI** the primary and default agent and hides the other two (Claude Code,
Antigravity CLI) without removing them.

Facts about Kiro CLI used here come from kiro.dev (CLI reference, headless mode, built-in tools,
installation). Behaviour was first verified against a stand-in kiro-cli, then against a real Kiro CLI 3.2.1 on
Windows 11 (2026-11-12), which changed criteria 4.1, 4.5 and 6.3.

## Glossary

- **Shown agent:** an agent CLI offered in `--help`, the welcome page and `/settings`.
- **Hidden agent:** supported, but used only when named (`--agent`, `SELECLE_PROVIDER`) or when
  `SELECLE_AGENTS=all` is set.

## Requirements

### Requirement 1: Kiro CLI is the default agent

**User Story:** As a new user, I want selecle to run on Kiro CLI without choosing anything, so that
the Crypt and my spirits use my Kiro account.

#### Acceptance Criteria

1. WHEN no agent is named and no profile choice exists THEN selecle SHALL use Kiro CLI for spirits
   and the Crypt.
2. WHEN `SELECLE_PROVIDER` names an unknown agent THEN `currentProvider()` SHALL fall back to Kiro.
3. WHEN an engine or oracle is asked for an unknown provider THEN it SHALL return the Kiro one.
4. The provider list SHALL put Kiro first.

### Requirement 2: The other agents are hidden, not removed

**User Story:** As the maintainer, I want Claude Code and Antigravity hidden from users but still
working, so that I can test and demo with them and nothing breaks for old profiles.

#### Acceptance Criteria

1. By default, `selecle --help`, the welcome page and `/settings` SHALL mention only Kiro CLI.
2. WHEN `SELECLE_AGENTS=all` is set THEN all three agents SHALL be shown and selectable, as before.
3. WHEN `--agent claude` or `--agent antigravity` is passed THEN that agent SHALL be used for the run.
4. WHEN `--agent` names an unknown agent, or has no value THEN selecle SHALL exit with status 1 and
   list the shown agents.
5. WHEN a saved profile names a hidden agent and that agent is not shown THEN selecle SHALL switch
   the profile to Kiro once and print one notice saying how to get the old agent back.
6. WHEN the Agent row in `/settings` has only Kiro to offer THEN ◂ ▸ SHALL change nothing, save
   nothing, and say that selecle runs on Kiro CLI; no restart button SHALL appear.

### Requirement 3: Knowing who is signed in to Kiro

**User Story:** As a user, I want selecle to know whether I am signed in to Kiro, so that it can
guide me to sign in before anything runs.

#### Acceptance Criteria

1. selecle SHALL ask `kiro-cli whoami --format json` and read any JSON object loosely (an email
   anywhere is kept; `loggedIn: false` or "not logged in" text means signed out).
2. WHEN the CLI rejects `--format` as unknown THEN selecle SHALL ask plain `kiro-cli whoami` again.
3. WHEN `whoami` exits non-zero, prints nothing, or says "Not logged in" THEN the user SHALL count as
   signed out.
4. WHEN the user is signed out and `KIRO_API_KEY` is set THEN the user SHALL count as signed in
   (method "api key"). The key SHALL never be copied into the account, profile or logs.
5. WHEN kiro-cli is not installed THEN selecle SHALL say so and link to kiro.dev, even if
   `KIRO_API_KEY` is set.
6. The signed-out help text for Kiro SHALL mention `KIRO_API_KEY` as an alternative.

### Requirement 4: Kiro spirits

**User Story:** As a user, I want a spirit to run Kiro headless with only the file tools it needs,
so that it can edit files without running commands on my machine.

#### Acceptance Criteria

1. A spirit SHALL run `kiro-cli chat --no-interactive --wrap never --output-format stream-json
   --trust-tools=read,write,glob,grep` with the prompt as the last argument.
2. Spirits SHALL NOT be trusted with shell, web or AWS tools.
3. WHEN `SELECLE_NPC_MODEL` is set THEN `--model <id>` SHALL be passed.
4. WHEN the prompt is longer than 24,000 characters THEN it SHALL be written to stdin instead of the
   command line (Windows limits a command line to about 32,000 characters).
5. Each stream-json line SHALL become spirit events: `agent_message_chunk` text is joined into one
   spoken message, `tool_call` becomes an action (verb from `_meta.kiro.toolName`, target from
   `locations[0].path`), and `runFinished` ends the run (success only when `status` is
   `success`; summary from `finalText`). JSON is never shown as speech. Non-JSON lines fall back to
   the plain-text reader: tool lines ("Using tool: X", "Reading file: P",
   "Creating: P") become actions with a verb and target; spinner-only and "Thinking" lines become
   "brooding"; other lines become speech; carriage-return redraws keep only the final state.
6. The run SHALL end with the process. Exit 0 is success, with the last spoken line as the summary.
   A non-zero exit is failure, with stderr as the reason.

### Requirement 5: The Crypt on Kiro

**User Story:** As a user, I want the Crypt to answer through Kiro without touching any tools, so
that its answers are fast and safe.

#### Acceptance Criteria

1. The Crypt SHALL run `kiro-cli chat --no-interactive --wrap never` with no tools trusted.
2. The prompt SHALL go through stdin, whatever its length.
3. The answer SHALL be searched for the JSON plan even with a leading "> " or ANSI codes. A plain
   answer becomes the reply.
4. WHEN Kiro reaches for a tool and is refused THEN the Crypt SHALL ask once more, firmly (existing
   behaviour, kept).

### Requirement 6: Installing Kiro CLI

**User Story:** As a user without Kiro CLI, I want the tools page to help me install it.

#### Acceptance Criteria

1. The tools page SHALL list Kiro CLI as the required agent by default.
2. On macOS and Linux, with curl present, it SHALL offer the official one-key install
   `curl -fsSL https://cli.kiro.dev/install | bash`.
3. On Windows, with PowerShell present, it SHALL offer Kiro's official installer
   `irm https://cli.kiro.dev/install.ps1 | iex` (served by Kiro, not listed in the docs; it checks
   the MSI's SHA-256). Without PowerShell it SHALL give the kiro.dev link.
4. WHEN `SELECLE_KIRO_BIN` names an existing program by full path THEN Kiro CLI SHALL count as
   installed even if it is not on the PATH.

# Design: Kiro CLI as the primary agent

## Overview

The three agent CLIs stay behind one provider table (`src/auth.js`), one engine table
(`src/npc/engines.js`) and one oracle table (`src/crypt.js`). The change is mostly about **which
entries are offered**, plus stronger Kiro-specific code. Hiding is a view filter
(`shownProviders()`), not a removal, so existing tests, the own-AI mode for friends, and old
profiles keep working.

```
             ┌──────────── auth.js ────────────┐
--agent ───▶ │ SELECLE_PROVIDER ─▶ currentProvider() ─▶ pickEngine / pickOracle
profile ───▶ │ (bin/selecle.js resolves at start) │        (fallback: DEFAULT_PROVIDER = kiro)
             │ shownProviders(): ['kiro']        │ ─▶ --help, welcome page, /settings,
             │   or all three if SELECLE_AGENTS=all     profile error messages
             └──────────────────────────────────┘
```

## Components and Interfaces

### `src/auth.js`
- `PROVIDERS` order: `kiro`, `claude`, `antigravity`.
- `PRIMARY_PROVIDER = DEFAULT_PROVIDER = 'kiro'`, `HIDDEN_PROVIDERS`.
- `showAllAgents()`, `shownProviders()`, `isShown(id)`.
- `parseKiroStatus(text, code)`: exit code first, then signed-out phrases, then JSON (loose),
  then text ("Logged in with X" becomes the method).
- `PROVIDERS.kiro.status(runner)`: `whoami --format json`, falling back to `whoami` on an
  unknown-flag error. If signed out with `KIRO_API_KEY` set, the result is `{ signedIn: true,
  method: 'api key' }`. If the program is missing (ENOENT), the result is always `missing`.

### `src/npc/engines.js`
- `KIRO_SPIRIT_TOOLS = ['read','write','glob','grep']`. These are the Kiro CLI 2.x tool names;
  `fs_read` and `fs_write` are older aliases.
- `kiroArgs(prompt, { tools, model })` returns `{ args, input }`. `input` is the prompt when it is
  longer than `KIRO_MAX_ARG` (24,000), otherwise `null`.
- `kiroStreamParser()` (one per run) reads `--output-format stream-json`: `{type, data}` lines,
  ACP `sessionUpdate`s and a final `runFinished`. Shapes were copied from a real 3.2.1 run.
  In plain-text mode Kiro 3.x prints tool activity on stderr only, which is why spirits use JSON.
- `parseKiroLine(line)` (fallback for non-JSON lines) turns one line into events. Kiro's plain-text format is not specified, so
  matching is loose and every unmatched line becomes speech.
- `cliEngine` gained `input` (written to stdin) and carriage-return folding, both shared with
  Antigravity.

### `src/crypt.js`
- `argOracle({ ..., viaStdin })`: when set, `argsFor(null)` is called and the prompt is piped in.
- `KIRO_ORACLE_ARGS = ['chat','--no-interactive','--wrap','never']`, with no `--trust-tools`.

### `bin/selecle.js`
- Usage text names Kiro only. The `--agent` line appears only with `SELECLE_AGENTS=all`.
- At startup, `--agent` / `SELECLE_PROVIDER` wins (any known agent, hidden or not; unknown or empty
  exits 1). Next comes the saved profile if its agent is shown. A saved hidden agent is moved to
  Kiro in the profile file, with one stderr notice on a TTY.
- `--real` now sets `SELECLE_ENGINE=real`. The old value `claude` only meant "not mock" and
  wrongly suggested Claude.

### `src/onboard.js`, `src/dialog.js`, `src/profile.js`, `src/tools.js`
- The welcome page and `/settings` cycle through `shownProviders()`. With one entry, the settings
  row says "the agent CLI selecle runs on" and ◂ ▸ only shows a notice.
- `editProfile` still accepts every known agent (hidden agents stay valid), but its error message
  lists only the shown ones.
- `toolList()` defaults to Kiro. It has the official install script for mac/linux, a link on
  Windows, and `path` (the agent's bin) so a full-path `SELECLE_KIRO_BIN` counts as installed.

## Data Models

No new storage. `profile.json`'s `provider` keeps its meaning. The only write is the one-time move
of a hidden agent to `kiro`.

## Error Handling

| Situation | Behaviour |
|---|---|
| kiro-cli missing | "Kiro CLI is not installed (kiro-cli was not found). Install it (https://kiro.dev/cli)…" |
| signed out | launch assistant offers `kiro-cli login` or pretend agents; help mentions `KIRO_API_KEY` |
| old kiro-cli without `whoami --format` | retried as plain `whoami` |
| prompt too long for a command line | sent through stdin |
| Kiro reaches for a tool in the Crypt | refused (nothing is trusted); asked once more, firmly |
| profile file not writable during the move | Kiro is used for this run anyway |

## Testing Strategy

- Unit tests (`test/agents.test.js`, `test/tools.test.js`) cover each acceptance criterion with
  stand-in runners and `node -e` stand-in CLIs. No paid calls.
- An end-to-end check ran the real `PROVIDERS.kiro.status`, `kiroEngine`, `kiroOracle` and the
  `selecle` command against a stand-in kiro-cli: node.exe with a `--require` preload that answers
  `whoami` / `chat` the documented way. It confirmed the argument lists, stdin delivery of a 26k
  prompt, a file written by a spirit, and the profile move.
- **Real kiro-cli (3.2.1, 2026-11-12):** `whoami` both ways, one Crypt message, and one spirit run
  through `kiroEngine` (writing, then reading, then speech, then done; the file was on disk).
